## Architecture check (Rules 6–9)

* **Owning module:** `vogue-vintage-vibes/src/routes/_authenticated/admin.audit.tsx`
  (new), `src/lib/api.ts` (new method + types), `admin.tsx` (nav + role gate).
* **Data flow:** `/admin/audit` → `api.adminAuditLogs()` → `request()` →
  `backend/app/routers/admin.py::audit_logs` → `public.audit_logs` (+ users /
  profiles joins). Backend unchanged.
* **Contract (unchanged, verified live):** `GET /admin/audit-logs` query
  `action`, `entity_type`, `entity_id`, `admin_id` (UUID), `limit` 1–500 (default
  100), `offset` ≥ 0. Response is a **bare array** newest-first — *not* the F2.5
  `Page<T>` envelope and no total — so `toPage()` is not used. Each row:
  `id, admin_id, admin_email, admin_name, action, entity_type, entity_id,
  old_values, new_values, ip_address, created_at`. 401 without a token, 403
  without the capability, error body `{detail}` → `ApiError`.
* **Paging:** the page asks for `limit = 26` and shows 25; a 26th row means a
  next page exists (the endpoint has no count). Offset = `(page − 1) × 25`.
* **Auth:** `StaffAudit` = `require_staff("audit")` = `{admin, super_admin}`
  from `user_roles` (`services/roles.py`). The frontend gate mirrors it: the
  `audit` tab key is added only to `ROLE_TAB_KEYS.admin` and `.super_admin`, so
  `admin.tsx`'s existing `tabAllowed` check renders «نقش «…» به این بخش دسترسی
  ندارد» for `order_manager` / `support` on direct entry, and the Outlet (and so
  the request) never mounts. Customers hit the existing "no admin access" notice;
  anonymous users are redirected by `_authenticated/route.tsx`. The backend stays
  the authority — a forced 403 still renders a Persian permission message.
* **Admin filter source:** `api.adminUsers()` (bare list, `StaffUsers` =
  `{admin, super_admin}`, the same set as `StaffAudit`), filtered client-side to
  staff roles. Only real UUIDs are ever sent as `admin_id`.
* **Reuse (Rule 7):** `formatFaDateTime` was added to the canonical
  `src/lib/format.ts` next to `formatFaDate` (none existed with a time part);
  no direct `fetch`; no new data-fetching pattern (plain `useQuery`).
* **Blast radius:** `api.ts` gained one method + two types (no existing member
  changed); `format.ts` gained one export; `admin.tsx` gained one tab key and one
  nav entry; `routeTree.gen.ts` regenerated by the TanStack router plugin.
  `grep -rn adminUsers src` → one existing caller (`admin.users.tsx`) —
  untouched.

## What is NOT done / open

* **New backend defect → `B5.1c` (discovered as `NEW-F55-1`, P3):**
  `GET /admin/audit-logs?admin_id=<not-a-uuid>` returns **500** (the `CAST(:admin_id
  AS uuid)` fails in Postgres). Admin-only caller and the UI only sends UUIDs, so
  not exploitable from the viewer; fix is to type the query param as `UUID`
  (→ 422). Recorded, not fixed (backend out of scope for F5.5).
* No total count / page numbers — the endpoint has none; adding one would be a
  contract change and was not needed.
* The admin filter loads the full `/admin/users` bare list and filters staff
  client-side; fine at today's size, and would want a staff-only query if the
  user table grows large.
* Action / entity labels are a frontend copy of the backend vocabulary; a new
  backend action still renders (raw name) but will not appear in the filter until
  it is added to `ACTION_LABELS`.
* Filters and page live in component state, not the URL (same as the sibling
  admin lists); a refresh resets them.
* No automated frontend test harness exists in this repo; the Playwright script
  lived in the session scratchpad and is not committed.
* Out of scope and untouched per the task: F5.6 role management, F5.9 coupon cap
  field, AB-FE-02 exports, AB-FE-05 products pagination, F4.3 AdminDataTable.
* Docs untouched on purpose: `backend/README.md` (no endpoint change),
  `infra/README.md` (no infra change), `vogue-vintage-vibes/README.md` (does not
  list admin routes), `design/SANDE_FULL_DEV_SPEC.md` (user's document).
